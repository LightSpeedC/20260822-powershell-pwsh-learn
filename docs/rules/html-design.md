# CLAUDE.md HTML Rule への変更案

参考実装 `how-to-claude-code.html` と現行ルール（CLAUDE.md 148〜189行）を突き合わせ、
**ルールの記述だけでは参考HTMLを再現できなかった箇所**を挙げる。

---

## 1. 色相の範囲を 280°→0° にし、(章数-1) で割る

現行：

> 色相(Hue)は279°(紫)を起点に、0°をまたいで減算方向に358°(赤)まで、計281°の範囲を**章数分**に均等分割する

問題が2つある。

### 問題A：「章数分に分割」が曖昧で、割り方を間違える

281÷章数 と読めるが、参考HTML（7章）の実測値 279 / 232 / 185 / 139 / 92 / 45 / 358 の刻みは
**281÷6 = 46.8**。つまり (章数-1) で割るのが正しい。
CLAUDE.md 183行の「例: 8→9章で 118.4→138.5」も (章数-1) でしか一致しない。

| 式 | 8章の5番目 | 9章の5番目 |
|---|---|---|
| 281÷章数 | 138.5 | 154.1 |
| **281÷(章数-1)** | **118.4** ✓ | **138.5** ✓ |

この解釈違いで `01-背景.html`（4章）は 281÷4 で計算し、**5章分の並びの先頭4つ**
（279 / 208.75 / 138.5 / 68.25）を使っていた。最後が赤にならず黄で終わっている。

### 問題B：281 は素数なので、どの章数でも割り切れない

281 は素数のため `281÷(章数-1)` は必ず長い小数になる（70.25 / 46.83 / 40.14 …）。
**範囲を 280°(紫) → 0°(赤) の280°に変える**と、280 = 2·2·2·5·7 なので主要な章数で整数になり、
さらに **終点が 0° になることで「0°をまたぐ」剰余計算そのものが不要**になる。

見た目のずれは全章 1〜2° で識別不能なため、既存HTMLを作り直す必要はない。

```
現行: 279 / 232.2 / 185.3 / 138.5 / 91.7 / 44.8 / 358
案:   280 / 233.3 / 186.7 / 140   / 93.3 / 46.7 / 0
ずれ: +1  / +1.1  / +1.4  / +1.5  / +1.6 / +1.9 / +2
```

なお章数が2以下になる構成では「章(h1)が2個以下の場合」のルール（ミニタイトルバーで区切り、
配下の項目見出しをh1にする）を適用するため、色を割り当てる対象は必ず3個以上になる。
早見表は3章から始めればよい。

**変更案（171行を差し替え）：**

> - 色相(Hue)は280°(紫)から0°(赤)まで減算方向に割り当てる（`hsl()`で指定。紫→青→緑→黄→橙→赤の順に経由する。マゼンタ側の短い経路は使わない）
> - **刻み幅は 280 ÷ (章数-1)**。n番目の章の色相は `280 - 刻み幅 × (n-1)`。最初の章が280°、最後の章が0°に着地する。章数(=h1の数)が2以下になる構成では「章(h1)が2個以下の場合」のルールを適用するため、この表は3から始まる
> - 彩度・明度は `--accent`: 彩度78%/明度25%、`--accent2`: 彩度58%/明度65%、`--soft`: 彩度28%/明度95%
> - 章数ごとの色相:
>
>   | 章数 | 各章の色相 |
>   |------|-----------|
>   | 3 | 280 / 140 / 0 |
>   | 4 | 280 / 186.7 / 93.3 / 0 |
>   | 5 | 280 / 210 / 140 / 70 / 0 |
>   | 6 | 280 / 224 / 168 / 112 / 56 / 0 |
>   | 7 | 280 / 233.3 / 186.7 / 140 / 93.3 / 46.7 / 0 |
>   | 8 | 280 / 240 / 200 / 160 / 120 / 80 / 40 / 0 |
>   | 9 | 280 / 245 / 210 / 175 / 140 / 105 / 70 / 35 / 0 |

## 2. 章のアクセント色は `.ch01` 形式のクラスで定義する（nth-child を使わない）

現行ルールは「章ごとに虹色を割り当てる」「目次バッジも同じ値に揃える」としか書いていないため、
`section:nth-child(n)` で章を数えて色を当てる実装になりやすい。この方式は

- 章の間に `<hr>` を挟むと nth-child がずれる
- h1・h2・th・目次バッジの4箇所に同じ色を個別に書くことになり、章を増減すると全部直す

参考HTMLは `--accent` / `--accent2` / `--soft` を **章クラスに定義**し、
`<section class="ch03">` と目次の `<li class="ch03">` の両方に同じクラスを付けている。
配下の h1・h2・th・pre は `var(--accent)` を参照するだけでよく、色定義は1箇所に集約される。

### クラス名はゼロ埋め2桁にする

参考HTMLは `.ch1`〜`.ch7` の1桁だが、**10章以上で `.ch1` が `.ch10` `.ch11` と前方一致する**。
CSS セレクタとしては別物なので表示は壊れないが、色相の振り直しでクラス名を一括置換するとき
`ch1` → `ch2` の置換が `ch10` を `ch20` に化けさせる。
**`.ch01`〜`.ch99` のゼロ埋め2桁**にすれば前方一致がなくなり、ソート順も章順と一致する。

**変更案（「タイトル・見出し」節に追記）：**

> - **章のアクセント色は `.ch01`〜`.ch99`（ゼロ埋め2桁）のクラスに `--accent` / `--accent2` / `--soft` の3変数で定義し、`<section>` と目次の `<li>` の両方に同じクラスを付ける**。h1・h2・thead・pre は `var(--accent)` を参照するだけにする
> - **`nth-child` で章を数える書き方は使わない**（章間に区切り要素を入れるとずれる）。**クラス名を1桁にしない**（`ch1` が `ch10` `ch11` に前方一致し、一括置換で壊れる）

## 3. 章見出しのセレクタを `section h1` に絞る（打ち消しをやめる）

h1 に「虹色グラデーション背景＋padding＋box-shadow」を当てるルールがあるため、
タイトルバー内の h1 がそれを継承して二重の箱になり、余白が過大になる。

参考HTMLはこれを**打ち消し**で解決している：

```css
h1           { background: linear-gradient(...); padding: 14px 20px; box-shadow: ...; }
.titlebar h1 { background: none; box-shadow: none; padding: 0; margin: 0 0 10px; }
```

しかし打ち消しは**章側に装飾を足すたびに追随が必要**で、書き忘れると壊れる（今回の
「タイトルの上下余白が広い」はこれが原因）。

章の h1 は必ず `<section class="chNN">` の中にあるので、**セレクタを `section h1` に絞れば
タイトルバーに届かない**。`.titlebar h1` は打ち消しではなく、自分に必要な指定だけを持つ
独立した定義になる。

```css
section h1   { background: linear-gradient(...); padding: 14px 20px; box-shadow: ...; }
.titlebar h1 { margin: 0 0 10px; font-size: 2.1em; color: #fff; }   /* 打ち消し不要 */
```

### 検討した他の案

| 案 | 内容 | 評価 |
|---|---|---|
| A | `h1` のまま＋打ち消しCSS | 章側を変更するたび追随が必要 ❌ |
| **C** | **`section h1` に絞る＋`.titlebar h1` は独立定義** | **打ち消し不要。採用** ✅ |
| B | タイトルを `<div class="doc-title">` にする | 文書の見出し構造からタイトルが消える ❌ |
| D | タイトル=h1、章=h2 に格下げ | HTML的には最も正しいが、既存ルールと全ファイルの作り直しが必要 ❌ |

### 付随：`--accent` が未定義になる穴

`h2` `h3` `pre` `th` も `var(--accent)` を参照しているため、`.chNN` の外
（章1の前の「はじめに」、章の後の「まとめ」等）に置かれると変数が未定義になり色が消える。
`:root` に既定値を置いて防ぐ。既定を**紺**にすると、章に属さない要素が
タイトルバー・目次・フッターと同系色に揃う（`--soft: #f2f5fb` は目次の背景色と同値）。

**変更案（「タイトル・見出し」節に追記）：**

> - **章見出し(h1)のスタイルは `section h1` にスコープする**。`h1` 単独のセレクタにするとタイトルバー内の h1 にも降りかかり、箱が二重になって上下余白が過大になる
> - **タイトルバー内の h1 は `.titlebar h1` として独立に定義する**（font-size・margin・color だけを書く）。`background: none` / `box-shadow: none` のような打ち消しは書かない。打ち消しは章側に装飾を足すたびに追随が必要で、書き忘れで壊れる
> - **`--accent` / `--accent2` / `--soft` は `:root` にも既定値を置く**（`--navy1` / `--navy2` / `#f2f5fb`）。章クラスの外に置いた「はじめに」「まとめ」等の h2・pre・table で変数が未定義になり色が消えるのを防ぐ。紺を既定にすると、章に属さない要素がタイトルバー・目次・フッターと同系色に揃う

## 4. 基本レイアウトの寸法を明記する

現行ルールに本文幅・本文サイズの記述がなく、狭すぎる幅（900px以下）を選ぶと
左右が余って本文の改行が増える。

参考HTML実測値：

| 項目 | 値 |
|------|-----|
| コンテンツ幅 | `max-width: 1080px` ＋ 左右 `padding: 0 20px`（→ **1400px / 左右 30px を採用**） |
| 本文 | `font-size: 15.5px` / `line-height: 1.85` |
| 見出し等 | すべて `em` の相対指定（h1 `1.5em` / h2 `1.16em` / h3 `1.02em` / code `0.9em` / table `0.93em`） |

**変更案（新設「レイアウトの基本寸法」節）：**

> - **本文の折り返し幅は `max-width: 1400px`、左右に `padding: 0 30px`** を取る。タイトルバーは全幅にし、内側の `.inner` とフッターも同じ 1400px ／ 左右 30px に揃える
> - **本文は `font-size: 15.5px` / `line-height: 1.85`**。見出し・code・table のサイズは `em` の相対指定にして本文サイズに追従させる

## 5. 余白の基準値を明記する

「隙間が大きい／小さい」の調整は毎回やり直しになるため、基準値を持つ。
参考HTML実測値：

| 要素 | padding | margin |
|------|---------|--------|
| タイトルバー | `34px 20px 30px` | — |
| section | `4px 26px 26px`（上は h1 の margin があるので詰める） | `34px 0` |
| h1 | `14px 20px` | `26px 0 20px` |
| h2 | `6px 12px` | `30px 0 12px` |
| h3 | `0 0 3px` | `20px 0 8px` |
| pre | `13px 16px` | — |
| th / td | `9px 12px` | — |

**変更案（新設「レイアウトの基本寸法」節に追記）：**

> - **余白の基準値**（実測で調整する前の初期値）: タイトルバー `34px 30px 30px` ／ フッター `18px 30px 0` ／ section `4px 26px 26px`・`margin: 34px 0` ／ h1 `14px 20px`・`margin: 26px 0 20px` ／ h2 `6px 12px`・`margin: 30px 0 12px` ／ th・td `9px 12px`。section の上 padding を詰めるのは、先頭の h1 が自前の上 margin を持つため。タイトルバー・フッターの左右は本文の `padding: 0 30px` に揃える

## 6. グラデーションの角度を用途で統一する ＋ SVG図の塗り

現行ルールは「2色グラデーション」としか書いておらず、角度がばらつく。
参考HTMLは4種類に統一している：

- **`135deg`** … タイトルバー（左上→右下、面が広い要素）
- **`100deg`** … h1・thead・目次バッジ・バッジ（ほぼ左→右、横長の帯）
- **`180deg`** … section 背景・pre 背景（上→下のフェード）
- **`90deg`** … h2 背景（左→右で透明にフェード）

### SVG図の箱は「下が濃く、上が明るい」

図の箱は**下から上に明るくなる**縦グラデーションで塗る。CSS の `0deg` に相当し、
section・pre の `180deg`（上が濃い）とは**逆向き**になる。箱が下から光を受けて
浮き上がって見えるため、章見出しの帯（横方向）と図（縦方向）が視覚的に区別できる。

SVG の座標系は **y=0 が上、y=1 が下**なので、下→上は `y1="1"` → `y2="0"` と書く。

```svg
<linearGradient id="g-01-3a" x1="0" y1="1" x2="0" y2="0">
	<stop offset="0" stop-color="var(--accent)"/>   <!-- 下＝濃い -->
	<stop offset="1" stop-color="var(--accent2)"/>  <!-- 上＝明るい -->
</linearGradient>
```

### SVGで踏みやすい3つの罠

**罠1: `<defs>` 内の id はページ全体で一意でないと全図が同じ定義を参照する**

複数のSVGが同じ `id="grad1"` を持つと、ブラウザは文書順で最初の1つだけを使う。
gradient だけでなく **marker・clipPath・filter も同じ**で、矢印の marker を使い回すと
全部の図が1枚目の色の矢印になる。`id="g-01-3a"` のように
**ファイル番号-図番-連番**を含めて衝突を防ぐ。

矢印は `<marker>` を使わず **`<line>` ＋ `<polygon>` で直に描く**のも有効。
id を増やさずに済み、色を1つずつ指定できる。

**罠2: `var(--accent)` は gradient を書いた位置で解決される**

インラインSVGはCSS変数を継承するので `stop-color="var(--accent)"` で章の色を使えるが、
変数は `<stop>` が置かれた位置のカスケードで解決される。
**gradient は必ずその章の `<section class="chNN">` の中に書く**こと。
ページ先頭に共通の defs を置くと、章クラスの外なので `:root` の紺にフォールバックする。

**罠3: 箱の中の文字が読めなくなる**

下端が `--accent`（明度25%）なので黒文字は読めない。**箱の中の文字は `fill="#fff"`** にする。
「文字色と背景色はセットで指定する」の絶対ルールがSVGにも適用される。

### 複数を比較する図はカラフルにする

DOS / Bash / PowerShell / Node.js を並べるような比較図は、**箱ごとに色相を変える**。
色相は章と同じ虹色レンジ（280°→0°）から選び、彩度・明度は章と同じ
（下 `78%/25%`、上 `58%/65%`）にすると資料全体で色の質感が揃う。

**変更案（新設「SVG図」節）：**

> - **グラデーションの角度は用途で固定する**: タイトルバー `135deg` ／ 横長の帯（h1・thead・目次バッジ・バッジ）`100deg` ／ 上下フェード（section・pre）`180deg` ／ 左右フェード（h2）`90deg`
> - **SVG図の箱は下から上に明るくなる縦グラデーションで塗る**。`<linearGradient x1="0" y1="1" x2="0" y2="0">` に 下＝`--accent`（濃い）→ 上＝`--accent2`（明るい）の2ストップを置く。SVGは y=0 が上なので `y1="1"` が下になる
> - **`<defs>` 内の id（gradient・marker・clipPath・filter 等）はすべてページ全体で一意にする**（`g-01-3a` のようにファイル番号-図番-連番を含める）。同じidが複数あるとブラウザは文書順で最初の1つだけを使い、他の図が全部その定義を参照してしまう。矢印は `<marker>` を使わず `<line>` ＋ `<polygon>` で直に描くと id を増やさずに済む
> - **gradient はその章の `<section class="chNN">` の中に書く**。`stop-color="var(--accent)"` は `<stop>` の位置で解決されるため、ページ先頭の共通 defs に置くと `:root` の紺になってしまう
> - **箱の中の文字は `fill="#fff"`** にする（下端が明度25%で黒文字が読めないため）
> - **複数の対象を並べる比較図は箱ごとに色相を変える**。色相は章と同じ虹色レンジ（280°→0°）から選び、彩度・明度は下 `78%/25%`・上 `58%/65%` に揃える
> - **SVGは `viewBox` を必ず付け、`width` 属性は書かずに `max-width: 100%; height: auto;`** で伸縮させる

## 7. 目次バッジに `max-width: 100%` を付ける

現行ルールは「固定幅で揃える」としか書いていないため、
ウィンドウを狭めたときバッジが親からはみ出す。

参考HTML：`width: 320px; max-width: 100%; white-space: normal;` ＋ `-webkit-line-clamp: 2`。
`display` は `-webkit-box`（line-clamp のため）で、`flex` は親の `ol` 側に付ける。

**変更案（「目次」節を修正）：**

> - **バッジは固定幅で揃え、文字は左寄せにする**。親の `ol` に `display: flex` ＋ `flex-wrap: wrap` ＋ `gap: 8px`、バッジ自身は `display: -webkit-box` ＋ `-webkit-line-clamp: 2` ＋ `white-space: normal`。**幅は `width: 310px` を初期値とし、必ず `max-width: 100%` を併記する**（狭い画面で親からはみ出さないため）

## 8. h3・pre・table の仕上げを追記する

現行ルールは h1・h2・thead には触れているが、h3・pre・td に色を伝播させる指定がない。
参考HTMLは以下でアクセント色を末端まで届けている：

```css
h3  { border-bottom: 2px dotted var(--accent2); display: inline-block; }
pre { border-left: 5px solid var(--accent2); }
table { border-radius: 8px; overflow: hidden; }   /* thead の角を丸める */
td  { vertical-align: top; }
tr:nth-child(even) td { background: #fafbfe; }    /* ゼブラ */
```

**変更案（「タイトル・見出し」節に追記）：**

> - **h3 は `border-bottom: 2px dotted var(--accent2)` ＋ `display: inline-block`**（下線を文字幅で止める）。**pre は `border-left: 5px solid var(--accent2)`** でアクセント色を継承する
> - **table は `border-radius` ＋ `overflow: hidden`** をセットで指定する（指定しないと thead のグラデーションが角を突き抜ける）。**行は `tr:nth-child(even) td` で `#fafbfe` のゼブラ**にし、`td` は `vertical-align: top` にする

## 9. 注意喚起ブロック（callout）を定義する

「重要な結論」を囲む枠が現行ルールにない。参考HTMLは章のアクセント色を使った callout を持つ：

```css
.callout {
	background: linear-gradient(180deg, var(--soft) 0%, #ffffff 100%);
	border: 1px solid var(--accent2);
	border-left: 6px solid var(--accent);
	border-radius: 0 8px 8px 0;
	padding: 12px 18px;
	margin: 16px 0;
}
.callout strong { color: var(--accent); }
```

**変更案（「その他」節に追記）：**

> - **節の結論や警告は `.callout` で囲む**。`border-left: 6px solid var(--accent)` ＋ `--soft`→白の上下グラデーション ＋ `border-radius: 0 8px 8px 0`。中の `strong` は `var(--accent)` にする

## 10. 共通カラートークンとバッジの具体値を載せる

現行ルールは「紺色」「緑／赤／灰／オレンジ」と言葉で書いてあるだけで、毎回色を選び直すことになる。
参考HTMLの実値をそのまま基準値にする。

**変更案（「その他」節に追記）：**

> - **章に依存しない共通色は `:root` に置く**: `--navy1: #12224d` / `--navy2: #2f5fbf`（タイトルバー） / `--ink: #1c2330`（本文） / `--ink-soft: #4a5568` / `--line: #d9dfe8`（罫線） / `--code-bg: #f4f6fa`。`code` は `background: var(--code-bg)` ＋ `border: 1px solid var(--line)` ＋ `color: #17335f`
> - **バッジは 100deg の2色グラデーション**: 良い・完了 `#1d7a3c`→`#45b56c` ／ 悪い・リスク `#a51f22`→`#e05a5c` ／ 未実施 `#5a6472`→`#97a1ae` ／ 警告 `#b8620a`→`#f0a548`。いずれも `color: #fff`、`white-space: nowrap`
